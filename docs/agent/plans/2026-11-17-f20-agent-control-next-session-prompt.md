### Что должно получить управление через нейросеть

Внешний harness, например Codex или DSH, подключается к LLPlayer через MCP либо локальный API. Он использует выбранную владельцем облачную или локальную модель. Плеер предоставляет инструменты, доступные настройки, сведения о готовности и результаты работы. Модель выбирается и вызывается средствами harness. Для подключения новой совместимой модели достаточно настроить её в harness.

Сделай одну общую реализацию для Avalonia Windows/Linux с типизированными операциями приложения. MCP и API используют одни обработчики, каталог возможностей и управление заданиями. Каталог охватывает все существующие функции и настройки из согласованной матрицы, включая модели и их явное скачивание, медиа и дорожки, распознавание Whisper/OCR, субтитры, перевод, пакетную обработку, Watch Folder, экспорт, словарь/Anki, дубляж и диаризацию. Каждая строка матрицы должна получить проверенный результат реализации. Фактические ограничения ОС и фонового режима сообщай через доступность и причины.

Согласованная архитектура включает `LLPlayer.ControlHost` на portable `net10.0`, ASP.NET Core и MCP SDK. Этот display-free процесс владеет настройками, заданиями, ML-процессами и GPU-координатором. `LLPlayer.Mcp` предоставляет stdio bridge к нему. Avalonia оставляет у себя native playback, подключается через `ControlClient` и выполняет экранные действия через обратный канал UI-операций. GUI attach, API и MCP видят одни задания. Companion runtime, сборка и упаковка входят в поставку.

Поддержи одновременно управление открытым Avalonia-плеером и настоящую фоновую обработку с закрытым окном. Присоединение GUI показывает те же задания и состояние. Владение заданиями и общий GPU-координатор должны оставаться едиными при подключении нескольких клиентов, закрытии окна и повторном присоединении. Права управления охватывают все согласованные функции, сохранение настроек и скачивание моделей. Используй обычные контракты этих функций и явные параметры запроса.

Основной сквозной сценарий выглядит так. По заданию пользователя harness изучает возможности и текущие настройки, выбирает медиа/аудиодорожку и ASR-движок, создаёт субтитры, получает прогресс, запускает перевод и сохраняет выбранный результат. Тот же сценарий должен работать для нескольких файлов. Клиент получает идентификатор операции, следит за состоянием, может отменить её и получает подтверждение завершения либо конкретную ошибку. Успех команды означает достижение её результата, включая завершение вложенных стадий.

Перевод имеет два явных пути. Первый использует провайдер, выбранный в плеере. Второй передаёт исходные реплики модели в harness и принимает переведённые реплики обратно с привязкой к исходному набору, устойчивым идентификаторам и ревизии. Применение перевода проверяет актуальность набора и сохраняет его тайминги. Контракт учитывает неполные ответы и повторную отправку. Выбор языка перевода входит в задание. Существующий batch с его русским целевым языком требует явной адаптации к согласованному общему сценарию.

Длительные задания переживают разрыв соединения с клиентом. После аварии хоста незавершённая работа получает состояние interrupted. Продолжение запускается явно после проверки сохранённого состояния, источников и параметров. Повтор запроса с тем же ключом операции возвращает существующее задание и его результат. Прерывание, отмена, восстановление и запись выходных файлов сохраняют согласованность состояния и учитывают уже выполненные внешние действия.
