# F-13 Linux Word Library, Dictionary Lookup, and Export

## Summary
- Add the next Linux/Avalonia word-learning slice: default-Off dictionary lookup from subtitle clicks, a durable editable Word Manager library, and explicit TSV/APKG exports plus AnkiConnect operations.
- Preserve WPF behavior, engine defaults, existing word-list schema/first-wins deduplication, and pinned SQLite dependencies. Do not add automatic sentence translation or claim full translation/settings parity.

## Key Changes
- **Lookup and click snapshot:** reuse the existing `WordDefinitionService` and selector with a detached immutable click snapshot containing term, context, source/target languages, and translated status. Keep lookup lifecycle in the current Avalonia `FlyleafWordTranslator` integration where appropriate; provide reusable Core snapshot/library behavior without requiring a wholesale translator move. Respect `Data.IsTranslated` for overlay text separately from `SubtitleData.UseTranslated` for sidebar text. Translation and definition requests may run in parallel, share the operation token/generation, and fail soft/not-found-cache independently. Block Save while either request is pending. For already-translated clicked text, save the target-language term and leave unrelated lookup fields blank; permit same-language source-definition lookup.
- **Core word library:** add a durable Core `WordLibrary` that reuses the engine word-list store logic and the existing `SavedWord` JSON-array schema, including first-wins deduplication. Persist `LLPlayer.WordList.json` under XDG config. Write the candidate atomically before publishing it in memory; expose I/O failure without changing in-memory state. Preserve corrupt bytes, show a warning, and block mutations until external repair/replacement; do not add recovery/import UI or autosave a guessed replacement.
- **Avalonia Word Manager:** provide a singleton shadcn-token list with selected-word edit form, without a DataGrid dependency. `Term` is read-only; the other four existing word fields save immediately. Include filtering, delete, clear, and a deck name that lasts while the Word Manager window remains open; closing and reopening resets it to `LLPlayer`, and the deck name is not persisted. Use save pickers for explicit TSV and APKG exports; use the AnkiConnect send button for explicit network operations, not a file picker. Cancellation must drain before disposal.
- **Exporters/Core and native packaging:** move the existing portable Anki sender/APKG writer into Core while preserving public namespaces and existing WPF callers. Add injectable HTTP for deterministic AnkiConnect protocol tests and validate each protocol step, including the AnkiConnect version requirement and preparation errors. Reuse the exact existing WPF pinned packages: `Microsoft.Data.Sqlite` 9.0.17, `SQLitePCLRaw.bundle_e_sqlite3` 3.0.3, and cached `SourceGear.sqlite3` 3.50.4.5 / `libe_sqlite3.so`; no version upgrade or new dependency family. The Linux package places `libe_sqlite3.so` at its root per native-loader contract. Update the dependency/license baseline and Linux package allowlist narrowly, with negative package checks and native APKG ZIP/SQLite proof. Ship full applicable license text and attribution: Microsoft.Data.Sqlite.Core MIT, SQLitePCLRaw components Apache-2.0, and SourceGear's SQLite 3.50.4 Public Domain notice.
- **Release and local desktop integration:** publish under the unique path `artifacts/f13-words-2026-10-03/`. After verification, update the owner's existing desktop launcher to the fresh package. Preserve the prior installed package and all user XDG data; record the launcher/package verification receipt. A package publish alone is not deployment evidence.
