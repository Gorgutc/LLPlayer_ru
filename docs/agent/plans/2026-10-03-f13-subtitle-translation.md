# F-13 Linux Subtitle/Sentence Translation

## Summary
- Add opt-in, per-slot sentence/subtitle translation to the Avalonia Linux app, using the existing engine `SubTranslator` and the provider settings/target/chat records already used for word translation.
- `SentenceProvider` defaults to `Off`; missing fields in existing translation settings remain Off. Both primary/secondary session toggles start Off and are not persisted.
- Preserve word-click behavior and WPF defaults. This is one bounded parity slice, not full F-13 point-3 parity.

## Key Changes
- **Settings:** add the detached `SentenceProvider` selection to `TranslationSettings` and its `LLPlayer.Translation.json` round-trip/validation. Reuse the current concrete provider records, target language, and chat configuration; do not duplicate provider credentials or create a second translation file or migrate the full player config. Settings load/save must not make health/probe requests; applying saved settings may resume ordinary translation for slots explicitly enabled in the current session. Off/unconfigured startup makes no requests.
- **Per-slot UI:** expose independent Word provider and Sentence provider choices plus an explicit **Edit provider settings** selector for the shared concrete provider records. Add independent primary/secondary session toggles, both initially Off and not persisted. Enabling a slot schedules translation through Flyleaf's existing ahead-translation path; disabling it requests cancellation and drains the active consumer before teardown. The controls expose clear status/error text; there is no new progress percentage.
- **Portable engine lifecycle:** extend/integrate existing `FlyleafLib.MediaPlayer.Translation.SubTranslator` for the portable Avalonia host under the repository's `#if !WINDOWS` convention, with an awaitable cancel/reset/dispose boundary and post-await stale-work guard. Reuse its existing translation service factory, cue/context policy, and caches instead of implementing a second translator or coordinator. Gate work through the existing Core `RecognitionActions` `Task.Run` path. The Linux/Avalonia integration must cancel/drain on toggle-off, settings/provider/endpoint/chat/target changes, media/track replacement, and host shutdown. Windows behavior and defaults remain unchanged.
- **Cache and display correctness:** invalidate previously generated translated-cue cache when effective provider, endpoint/chat settings, target, media, or track changes—even when the enum provider is unchanged. Discard canceled/old-generation results before mutating cues or UI. Keep overlay and sidebar provenance tied to the text each actually displays (`SubtitleData` translation provenance versus `UseTranslated` selection), and coalesce cue notifications so ahead-translation updates do not flood the UI.
- **Release:** no new dependency, model, native library, or runtime inventory is expected. Publish to a unique `artifacts/f13-subtitle-translation-2026-10-03/` path, validate package contents, and update the existing desktop launcher to the verified package. Preserve the installed words package and all XDG user data; record the deployment receipt.
