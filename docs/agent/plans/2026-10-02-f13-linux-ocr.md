# F-13 Linux OCR Engine Implementation Plan

## Summary
- **Status: IN PROGRESS (engine, gates, and final review verified; owner workflows pending).** The portable engine slice uses the system `libtesseract.so.5` C API through an `IOCRService` adapter registered at engine bootstrap.
- This adds engine support only. No OCR controls/UI, `LLPlayer.Core`, Avalonia OCR workflow, or Windows/WPF behavior changed.
- Starting point: `codex/f13-linux-asr`, working tree over baseline `57e900da4684cc6a9e664f5ada514ecc8ecb2c05`; it contains prior approved, uncommitted ASR changes. ASR receipts do not count as OCR evidence.

## Key Changes
- Added `FlyleafLib/Platform/Portable/MediaPlayer/TesseractOCRService.cs` and `TesseractNative.cs`; bootstrap registers the adapter through `SubtitlesOCR.ServiceFactory`. Native OCR uses OEM3/PSM3 and RGB24 input, reusing existing monochrome/padded bitmap preparation and English post-processing.
- Preserve `TesseractModel` language mapping (`nb`/`no`, Chinese regional variants and CJK spacing). API engines are owned/freed per track; the native library binding stays loaded for process lifetime. Cancellation is observed between cues, while an in-flight native OCR call is not instantly cancellable.
- Runtime prerequisites are system Tesseract 5.x and system tessdata. Standard `TESSDATA_PREFIX` is honored and normalized (including valid relative paths); invalid explicit paths and missing library, data directory, language data, or corrupt model return initialization errors. No new NuGet, bundled native library, or public config default was added.
- Maintain the approved F-13 sequence: engine ASR/OCR → `LLPlayer.Core` → Avalonia UI integration → parity items 3–14 → Windows Avalonia GPU/audio/package → owner smoke → WPF retirement.
