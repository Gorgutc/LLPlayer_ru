# Product Behavior Contract

This document freezes the current user-facing behavior from `main`. Future work should change only the requested surface and preserve unrelated behavior.

## Product Position

LLPlayer is a specialized Windows media player for language learning. It is not a general replacement for VLC/mpv. The core value is video playback plus subtitle-centric learning workflows.

## Core Functions To Preserve

- Play local media files and online video URLs.
- Accept one command-line path/URL and open it at startup.
- Drag/drop and context-menu based media/subtitle workflows through the Flyleaf host.
- Dual subtitles: primary and secondary subtitle tracks, both text and bitmap.
- Subtitle overlay on the video surface and optional subtitles sidebar.
- Subtitle seeking, sidebar search, current/previous/next subtitle context, and per-item seek.
- ASR subtitle generation through Whisper.net/whisper.cpp and faster-whisper.
- Batch subtitles for local folders: scan video files, run ASR per video, translate completed subtitle sets to Russian through the configured Translate provider, and save `video.ru.srt` beside each video. A batch run keeps running if the main video window is closed (the app minimizes to the system tray and shows overall progress there + on the batch window's taskbar button); a video row can be double-clicked to open it in the player. Closing the batch window itself while a run is in progress also minimizes it to the tray and keeps processing (re-open from the tray menu); the run is stopped only via the Cancel button or the tray's Quit. Background-friendliness options (default on) keep the machine responsive during long runs: "smooth" mode never runs ASR and translation at the same time (so a GPU ASR engine and a local-LLM translator don't both saturate the GPU), and "run ASR on CPU while I work" transcribes the next audio chunk on CPU (faster-whisper) instead of the GPU while the keyboard/mouse are active, switching back to GPU after a configurable idle period — the chunk in flight finishes on its current device, so nothing already computed is lost.
- Clear subtitle-track switching: every available track — embedded (in the video), external files auto-detected beside the video or downloaded, and ASR — is presented with its language and source and can be assigned to the primary (1st) or secondary (2nd) slot from the right-click Subtitles ▸ Subtitle Tracks menu (both slots) or the sidebar "Subtitle tracks" quick switcher.
- OCR for bitmap subtitles through Tesseract and Microsoft OCR paths.
- Translation through Google V1, Bing, Azure, DeepL, DeepLX, Ollama, LM Studio, KoboldCpp, OpenAI, OpenAI-like, Claude, and LiteLLM settings.
- Context-aware translation for LLM-like providers through chat/context configuration.
- Word lookup and browser/search actions from subtitle text.
- Text subtitle word actions: left-click word lookup, left-drag phrase lookup, middle-click sentence lookup, right-click word actions, modifier-triggered last search, pause-on-selection, popup close-on-play, and optional copy-on-selection.
- Subtitle download through OpenSubtitles provider and subtitle export to SRT, WebVTT (`.vtt`), or plain text (`.txt`), chosen by a format selector in the export dialog.
- AI Insights (F-07, since 0.3.18): an LLM-powered action that summarizes the current transcript and/or extracts key study vocabulary from it, opened from right-click Subtitles ▸ AI Insights.
- Online video integration through the `YoutubeDL` plugin and release-downloaded `yt-dlp.exe`.
- Fully customizable keyboard shortcuts and mouse controls.
- Built-in CheatSheet for keyboard and mouse actions, plus a `Ctrl+K` command palette to search and run any bound action.
- Dark theme with configurable colors and app settings.

## User-Facing Invariants

- Preserve dual subtitle model unless the user explicitly requests a redesign.
- Preserve primary/secondary distinction in overlay, sidebar, copy actions, sizing, and translation.
- Preserve text and bitmap subtitle support; do not regress bitmap positioning or OCR flow when touching text subtitle code.
- Preserve app-level actions through `LLPlayer/Services/AppActions.cs`; do not bypass this layer for user-visible commands.
- Preserve `Save & Close` versus `Close` behavior in settings: only the save path writes config files.
- Preserve CheatSheet discoverability for shortcuts and mouse behavior when actions change.
- Preserve Settings Keys as an editable shortcut workflow with Add/Load/Apply, clone/delete, duplicate blocking, grouped actions, custom actions, key capture, and Enter commit.
- Preserve CheatSheet as a searchable, executable action surface with Keyboard/Mouse tabs and enabled-binding filtering.
- The Command Palette (`Ctrl+K`) is an additive, optional surface over the same enabled key bindings; it does not replace CheatSheet or the context menu.
- Error routing: two recoverable configuration cases on the interactive ASR path are non-blocking actionable snackbars — the missing-ASR-model case (DOWNLOAD deep-link, plus a one-time first-run onboarding hint) and, since 0.3.15, the missing Visual C++ Redistributable case for whisper.cpp ASR (an INSTALL action that opens the Microsoft download page; see T-02 / `VcRedistChecker`). All other known errors — including translation/OCR configuration failures — remain blocking modals so they are not missed; the Tesseract-OCR missing-VC++ case is one such modal (the download URL is carried in its message text), and a missing-VC++ failure on the batch ASR path is likewise a modal: since 0.3.16 it is preflighted before the run starts and shown as a clean, actionable known-error modal carrying the same message plus an INSTALL action that opens the Microsoft download page (the batch dialog is a separate non-modal window, so a main-window snackbar would not reliably cover it; the modal is Topmost), replacing the earlier generic unknown-error popup. The word-translation config error keeps its existing one-shot in-popup snackbar. ASR completion shows a non-blocking confirmation in addition to the completion sound.
- Interactive ASR can be paused and resumed from the player-bar ASR status chip (F-04, since 0.3.17): a left-click pauses transcription at the next chunk boundary (a chunk is transcribed atomically, so the chunk in flight — including the external faster-whisper process — finishes first) and a further click resumes, KEEPING the subtitles produced so far. This differs from cancelling/disabling ASR, which clears them. Pause is interactive-only (the headless batch path is unaffected), applies to the whole run (both slots when dual-ASR), and a fresh run never starts paused. The chip's trailing icon reflects the running/paused state.
- A-B repeat (F-12, since 0.3.27) is an additive, opt-in playback loop between two user-set points; with no points set, playback is byte-identical to before. The player bar has an A-B button (left-click cycles Set A → Set B → Clear; right-click menu exposes the three explicit actions; the icon lights while a loop is armed) and the seek bar shows A/B markers plus a highlighted band between them (a separate overlay that leaves the buffering indicator untouched). When both points are set with A &lt; B, playback seeks back to A each time it reaches B (frame-accurate to A), keeping audio/subtitles in sync through the existing seek path (no new locking). The four actions (Set A / Set B / Clear / Toggle-cycle) are also customizable key bindings, unbound by default — assign them in Settings ▸ Keys; they appear in CheatSheet/Command Palette under the Playback group. The points are transient runtime state (not persisted; reset when a new file opens); A-B repeat takes priority over whole-file Loop Playback at end-of-file and is inert during reverse playback and for HLS-live streams. The waveform-visualization half of F-12 is not included.
- The empty (no-media) state offers Open File plus Settings and keyboard-shortcuts entries, and the right-click context menu includes a Settings entry.
- Preserve explicit user-selected export path for subtitle export. The export dialog offers a format (SRT / WebVTT / TXT); SRT and WebVTT carry inline italic (`<i>`) markup reconstructed from the cue's style ranges when exporting the original (untranslated) text, while TXT is plain transcript text only (no timings, no markup). Translated-text export carries no style markup (style offsets index the original text). The UTF-8 BOM option and the open-in-Explorer behaviour are preserved.
- AI Insights (F-07, since 0.3.18) requires an LLM provider and never silently falls back to a non-LLM translator. The model is chosen from the configured services: the subtitle-translation service if it is a configured LLM, else the word-lookup service if it is, else the first configured-and-usable LLM; when none is configured the action shows a known-error popup pointing the user to Settings ▸ Subtitles ▸ Translate (it does not run). The output language follows `TranslateTargetLanguage`; the original transcript text is analyzed by default (a toggle can analyze the translated text instead). The result is read-only in the dialog and exportable (copy / save-to-file); its extracted vocabulary can additionally be added to the global word list with the "Add to List" button (F-10, see below). The feature reuses the existing translation LLM settings and adds no new persisted config of its own. Long transcripts are handled by character-budget chunking with a map/reduce summary and per-chunk vocabulary merge; when a transcript exceeds the chunk ceiling it is sampled and the partial-coverage is surfaced in the dialog. The reply is never silently truncated: a model reply cut off by the token cap surfaces as a known-error popup advising a shorter range or a higher Max Tokens, rather than a half-result shown as complete.
- Word Manager (F-10, since 0.3.24) is a global cumulative word list persisted to `LLPlayer.WordList.json` beside the exe (additive — an absent file means an empty list; nothing changes for existing installs until the user saves a word). Words enter the list from two sources: the word-click translation popup's "Save word" button (saves the looked-up term, its shown translation, the subtitle cue as the example sentence, and the source/target languages; a click on already-translated text is stored as-is in the target language; Reading/Definition are left blank for the user to fill in later, unless the dictionary-definition feature auto-fills them — see F-11 below), and the AI Insights "Add to List" button (bulk-adds the extracted vocabulary). Dedup is by Term (case-insensitive, first-wins). The Word Manager dialog (right-click Subtitles ▸ Word Manager; non-modal `ShowSingleton`) lists all saved words in a DataGrid where Term is read-only and Reading/Translation/Definition/Example are editable in place (edits write through immediately), with a substring filter and per-row delete plus Clear All. Three export actions reuse the same five-field card model: a TSV file (Anki File ▸ Import; same format as the AI Insights TSV), an `.apkg` Anki deck package (a real SQLite collection + zip), and a live push to a running Anki via the AnkiConnect add-on at `localhost:8765` (it creates the deck and the "LLPlayer" note type, so no prior import is needed). The deck name is entered per session (default "LLPlayer", not persisted). `.apkg` building fails soft (a clear known-error popup, TSV/AnkiConnect remain available) and AnkiConnect reports a clear error when Anki is not running. Stable per-Term note GUIDs make re-export update rather than duplicate cards in Anki.
- Word definitions in the popup (F-11, since 0.3.25) are an opt-in addition controlled by `Subtitles.WordDefinitionServiceType` (default `Off`, which keeps the popup byte-identical to before). When enabled, the word-click popup shows a dictionary DEFINITION in a third row below the translation (in addition to it, not instead of it) and, on Save, auto-fills the saved word's Reading (phonetic) and Definition fields for Anki (filling exactly the two fields the F-10 word-click previously left blank). The provider follows the mode: `Auto` uses the free dictionaryapi.dev for English source words and the configured translation LLM for other languages (and as a fallback when the English dictionary has no entry for a word); `DictionaryApi` forces the English-only dictionaryapi.dev; `Llm` forces a configured-LLM definition written in the target/study language; `Off` disables the lookup. The LLM provider is resolved exactly as AI Insights resolves it (the configured translate/word LLM, else the first usable one) and the feature adds no new LLM config of its own. The lookup runs in parallel with the translation under the same cancellation token (a re-click cancels both) and is skipped only for an already-translated clicked word (a monolingual definition where the source and target language are the same — e.g. an English word defined in English, or a Russian word in Russian — is still useful, so same-language clicks are NOT skipped, unlike translation). Saving a word waits for an in-flight definition (the Save button reports "looking up the definition — try again in a moment" rather than persisting blank Reading/Definition that the term-dedup could not later update). It is fail-soft on this hot interactive path: a word missing from the dictionary, any transport/timeout error, a truncated/failed LLM reply, or no configured LLM all simply leave the definition row hidden — never a modal, and the translation still shows. Lookups are cached per word for the popup's lifetime (including not-found). The definition row is collapsed (zero height) when the feature is off or no definition was found, so the popup is unchanged on the default path.
- Preserve batch subtitle output as user runtime files beside source videos. Files that already have a non-empty `video.ru.srt` are detected at scan time, shown as `Completed`, and excluded from the default run; at run time an existing non-empty `video.ru.srt` is likewise marked `Completed` rather than reprocessed. Both are overridden when overwrite is explicitly enabled. Each scanned file carries an include checkbox (with a select-all/none header) controlling whether it is processed, and failed files can be retried individually (per row) or in bulk; an explicit retry forces reprocessing regardless of an existing output.
- Watch-folder auto-batch (F-09, since 0.3.22) is an opt-in batch mode (`WatchFolder` toggle, default off). When on, the batch window watches the selected folder (recursively when Recursive is on) and automatically processes new video files as they appear: a file is added to the list only after it has finished copying/downloading (its size and last-write time are stable across polls and it opens for shared read — a partial download is not transcribed), with the same eligibility rules as a manual scan (video extension, not already listed, skipped when output exists and overwrite is off). A newly-ready file auto-starts processing when no run is in progress; if a run is in progress it is queued and drained when the current run finishes (never two concurrent runs). The existing friendliness options (Smooth no-overlap, Run-ASR-on-CPU-while-active) and the Recursive/Overwrite settings apply unchanged. Watching continues while the window is minimized to the tray and stops when the dialog is closed, the toggle is turned off, or the app quits; if the watched folder becomes inaccessible the watch turns itself off with a known-error notice. An explicit Cancel stops the current run and does not auto-restart.
- LLM translation guards against degenerate (looping) replies: a reply detected as a repetition loop, or cut off by the token cap, triggers one anti-loop retry (non-zero temperature + frequency penalty); a reply that still loops falls back to the source text for that line rather than returning or caching the loop. Degeneration detection is source-aware: when the source subtitle line is itself legitimately repetitive (e.g. a shouted "quick, quick, quick…"), a faithful repetitive translation is not flagged as a loop — the reply's allowed repetition scales with the source's own repetition. In batch subtitle generation a per-line content failure (a degenerate/looping reply, truncation, or empty/null content) likewise falls back to the untranslated source text for that single line and the run continues, matching interactive playback; network/timeout failures, configuration/auth errors and cancellation still fail the file rather than silently emitting all-source output. Frequency/presence penalties are tunable in Settings → Translate. (Frozen-default flip 1.3: new configs no longer force `temperature=0`; existing configs keep their saved value. Local LLM backends apply a non-persisted default `max_tokens` cap so a runaway loop fails fast instead of running to the request timeout.)
- Whisper ASR (whisper.cpp) defaults to `NoContext` on (`condition_on_previous_text` off) so a hallucinated/looping window at the start of a video does not propagate a repetition loop across the transcript. (Frozen-default flip 1.5: new configs default on; existing configs are migrated once — see `config-data-contract.md`.)
- The whisper.cpp model downloader (Settings ▸ Subtitles ▸ ASR ▸ Download Model) lists quantized variants (q5_0 / q5_1 / q8_0) as first-class rows alongside each full model (since 0.3.21), each with its own per-file Downloaded status, download, and delete; quantized models are smaller and faster to run. The full (non-quantized) model is unchanged — same default selection, label, and on-disk `ggml-{model}.bin` file — and the Settings ASR model picker shows the chosen variant's label (e.g. `Base (q5_1)`). A (model, quantization) combination not published on the download server surfaces a clear "not available — try a different model or quantization" status instead of a raw HTTP error, leaving nothing half-downloaded.
- Whisper ASR (faster-whisper / faster-whisper-xxl) ships anti-hallucination decoding defaults on (`FasterWhisperConfig.AntiHallucination`, default on, since 0.3.6): the engine command gets `--condition_on_previous_text False` (a repetition loop no longer propagates), plus the more permissive `--no_speech_threshold 0.4` and `--vad_threshold 0.35` so speech that co-occurs with background music is not dropped as silence. Each flag is appended only when the user has not already set it in Extra Arguments (de-duplicated; an explicit user value wins), so the behaviour is additive and fully overridable. Turning the toggle off restores the engine's own defaults. An optional initial prompt (`FasterWhisperConfig.Prompt`, default empty, since 0.3.11) is passed as `--initial_prompt` (de-duplicated against Extra Arguments; an explicit `--initial_prompt` there wins): a short, normal-case sample of the expected language biases faster-whisper toward the correct language/script and casing, reducing foreign-script drift and ALL-CAPS output at the source. (See `config-data-contract.md`.)
- Generated subtitles are re-segmented for readability (default on, `Subtitles.ResegmentSubtitles`): an over-long Whisper cue is split into short, at-most-3-line cues (~48 characters/line as of 0.3.7, up from 2 lines / ~42 chars so a phrase that spans cues is less likely to be truncated) with proportionally redistributed timings, on the interactive ASR path, batch generation, AND loaded/sidecar/embedded text subtitles (as of 0.3.10: an over-long loaded cue — e.g. a `.srt` with a ~6-line block — is split (on line/character overflow only — the duration cap that paces a long ASR "wall of text" is NOT applied to loaded subs, so a cue an author deliberately holds longer keeps its timing) and re-timed proportionally across the resulting cues; bitmap/PGS subtitles and styled ASS cues (those carrying `SubStyles`) are left untouched, and a loaded cue that already fits passes through unchanged), and the translated text is wrapped to the same shape. The cap and line length are configurable in Settings ▸ Subtitles ▸ Re-segmentation; existing configs on the prior default are migrated once (see `config-data-contract.md`). Wrapping never splits a word and a cue that already fits is left untouched; line breaks are stored as `\n`. The default LLM translation prompts were also improved for accuracy (meaning over literal, tone/register preserved, output-only-the-translation); existing hand-edited prompts are preserved. Separately, ALL-CAPS normalization (`Subtitles.FixAllCaps`, default on, since 0.3.11) rewrites an ALL-CAPS generated (ASR) cue to sentence-case — random ALL-CAPS is a known faster-whisper(-XXL) artifact (previews/trailers/merged lines); a cue whose letters are predominantly uppercase and that has two or more words is normalized, while a short acronym, a single word, or normal mixed/title-case text is left untouched. It runs on the interactive ASR and batch generation paths only (NOT on loaded/authored subtitles), before re-segmentation.
- LLM subtitle translation defaults to context-window mode (`TranslateChatConfig.TranslateMethod = ContextWindow`, since 0.3.6). Each line is still translated to exactly one output line, but the surrounding source lines (`ContextWindowBefore`/`ContextWindowAfter`, default 6 each) are supplied as read-only context so a sentence split across cues is translated with the grammatically correct, inflected form (fixing literal, context-blind output such as a base/infinitive form where the running sentence needs a conjugated one). An optional second proof-reading pass (`GrammarCheckEnabled`, default on) re-sends the translated line to the LLM to correct target-language grammar, agreement, and fluency; if that pass fails or returns an empty/degenerate reply, the first-pass translation is kept (never lost). ContextWindow runs sequentially for LLM providers (the grammar pass already doubles per-line requests). The previous `KeepContext` and `OneByOne` methods remain selectable; a config still on the old default `KeepContext` is migrated once to `ContextWindow` while an explicit `OneByOne` choice is preserved (see `config-data-contract.md`). Non-LLM providers ignore the context window and translate the line as before.
- Batch subtitle generation is audio-track aware (default on, `PreferRussianAudio`): when a video has a Russian-tagged audio track, that track is transcribed so the subtitles come out in Russian and translation is skipped (no ru→ru); videos without a Russian track are transcribed in their language and translated as before. The batch list exposes a per-file audio-track picker ("Auto" prefers Russian, else the configured language order) and the player keeps its existing audio-track switch menu.
