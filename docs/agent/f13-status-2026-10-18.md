## Current Windows/Linux UI implementation

- `LLPlayer.Avalonia` targets portable `net10.0` with `win-x64` and `linux-x64` RIDs. Views, view models, resources,
  themes, dialogs and Core services are shared; the Windows build uses the Linux-developed UI directly.
- Windows uses the existing FFmpeg 8 DLLs, software BGRA rendering and app-local OpenAL Soft 1.23.1 from pinned
  `Silk.NET.OpenAL.Soft.Native`. The Windows package requires the .NET 10 runtime and x64 Visual C++ 2022
  redistributable. No FFmpeg upgrade or WPF release-flow replacement is included.
- `scripts/windows/verify-avalonia.ps1` runs portable engine/Core/Avalonia builds and test suites with a generated
  media/subtitle fixture and native checks. `test-package-avalonia.ps1` exercises positive/negative package rules;
  `publish-avalonia.ps1` produces the separate framework-dependent Windows Avalonia ZIP and checksum.
- The added `LLPlayer Windows Avalonia Build & Test` job in `build.yml` checks and packages the Windows host.
  Linux continues through `build-linux.yml`; the existing Windows WPF job stays required. Subsequent shared changes
  must pass both Avalonia platform gates and preserve WPF compatibility.
- Source presence and packaged Whisper CPU files do not establish Windows ASR/OCR support. Windows recognition,
  GPU rendering, real provider/Anki workflows and full F-13 parity remain separate acceptance work.

### Repairs in the shared Windows Avalonia slice

- The tracked Windows FFmpeg build is decoder-only (`--disable-encoders`), so portable PNG/BMP/JPEG media-frame
  snapshots could not find an encoder. Windows now falls back to the built-in GDI+ encoders loaded only from
  System32 when FFmpeg has no encoder, after the same shared deinterlace, HDR conversion, crop, rotation/mirroring
  and colour-filter pipeline. Linux retains the existing FFmpeg encoder path; no native-library upgrade is involved.
- The developer `--screenshot` helper now writes a canonical 96-DPI PNG, one pixel per layout DIP. This avoids
  duplicate HiDPI transforms in Avalonia's immediate shadow rendering at 150%/200% scale. It changes developer
  evidence capture, not the media-frame snapshot size or the desktop's DPI-aware layout. Pixel regression tests
  inspect the arranged toast accent/title positions and output size at 100%, 150% and 200% scaling.
- Prior Windows candidate gates/package checks and a first-package light-theme video/audio smoke preceded these
  repairs. They are not final-tree evidence. Initial dark-theme cold-open observations were partial; the existing
  Lingua subtitle-language initialization delay remains open. The final local unfiltered suites, rebuilt package
  and bounded dark/light native smoke are recorded above. Published source candidate CI/review also passed;
  later documentation/merge checks and broader manual acceptance remain separate.
