## Bounded text-subtitle outline thickness

The owner selected a separate shared Windows/Linux Avalonia stage after the position slice: independently
persist primary `AppPrefs.SubtitleOutlineThickness` and `SecondarySubtitleOutlineThickness` in
`LLPlayer.Avalonia.json`. Missing values keep the existing `3`/`2.5` DIP widths; finite values clamp to 0–8 DIP,
and non-finite values fall back to the corresponding slot's own default. Settings owns nine detached fields
(the previous seven plus these two); Save & Close persists before applying, Close/Esc discard edits, and both
widths restore after restart. Invalid or out-of-range raw numeric input blocks Save visibly.

Zero disables the black text outline while retaining the existing shadow rendering. Shadow pen width already
derives from outline thickness (`2 * thickness + 2`); changing thickness makes no pixel-identical-shadow claim.
The stage does not change WPF's separate shared `SubsStrokeThickness` default `3.2` and font scaling, bitmap
subtitles, sidebar styling or engine configuration. It establishes neither WPF geometry parity nor full Settings/F-13 parity.
The bounded render fix also invalidates `SubtitleText`'s cached layout/geometry when outline thickness changes.
This prevents a fractional `3` → `3.1` change from retaining stale geometry compared with a fresh control;
the existing render algorithm is unchanged, without adding an `AffectsRender` registration.
Product implementation and regressions: `14751762a1fe88b6650b8d1b4b6f2d18d82024da`.
