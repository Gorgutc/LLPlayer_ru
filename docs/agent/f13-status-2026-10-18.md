## Bounded text-subtitle layout (WPF Position / Size, text half)

The separately owner-approved 2026-10-24 shared Windows/Linux design-transfer stage adapts the text-layout half of
the WPF `Subtitles > Position / Size` page to the one Avalonia transport. Product
`baa6dc162e2a7363e55a1217224a1c4b585e0054` (eight app files and three test files, one of them an existing position
regression updated to the new geometry seam) is based on merged main
`d646f194f4d83f9ce182d8d74dd03919489f5faa`. No engine, WPF, Core, dependency or packaging change is included; no new
package or migration is introduced. Horizontal line alignment is an **additive Avalonia extension**, not a WPF port:
WPF hard-codes centered subtitle lines (`AlignableWrapPanel.HorizontalContentAlignment=Center`), so this option is
deliberately new behavior only in the shared Avalonia front-end.

Five additive preferences in `LLPlayer.Avalonia.json` are `SubtitleWidthPercent` (whole `Int32`, 1–100, default `100`),
`SubtitleMaxWidth` (DIP, 0–4000, default `0` = no cap), `SubtitleIgnoreLineBreak` (bool, default `false`),
`SubtitleLineAlignment` (`Center`/`Left`/`Right`, default `Center`) and `SubtitlePrimarySecondaryDistance` (DIP, 0–200,
default `2`). Settings ownership rises from twenty-two to twenty-seven fields. Every default restores the previous
look exactly: full padded width, no cap, hard cue line breaks, centered lines and the existing 2-DIP gap. Normalization
clamps the width, max width and distance, falls non-finite numbers back to their defaults and normalizes an
unsupported alignment string to `Center`; malformed whole-file JSON keeps the existing load policy. The settings list,
the persisted normalization and the overlay/preview mapping now share one owner (`SubtitleLayoutOptions`).

The shared overlay box is now centered with a computed width: the approved 48-DIP side margins are folded into
`(video-column width - 96) * widthPercent / 100`, capped by the optional max width, and never below 1 DIP. At `100`
percent the resulting geometry is unchanged; `SubtitleBottomOffset` stays the only vertical margin (the WPF vertical
percentage position is deliberately not ported, and bitmap positioning keeps its frozen contract). The primary/secondary
gap follows the distance preference. Ignore line breaks reuses the canonical portable
`FlyleafLib.SubtitleTextUtil.FlattenText` — the same helper WPF applies — so dash lists keep both lines and blank-line
series collapse to one space instead of the ad-hoc newline-to-space replacement. Alignment and that canonical text are
shared by measurement, outline/background geometry and word-hit testing (`FormattedText.Trimming = None` keeps drawn
wrapping equal to the measured `TextLayout`), and option changes invalidate the cached layout, measure and visual.
Pixel tests confirm the drawn glyph columns for Left/Center/Right, not only the hit-test columns.

Settings exposes detached raw editors for width, max width and distance plus an alignment selector and an Ignore line
breaks checkbox; invalid raw values block Save visibly, and programmatic draft changes keep the editors in sync. Save
merges all twenty-seven owned fields into a fresh candidate, persists before applying, preserves unrelated values, and
keeps the failure/Close/Esc/restart transaction. The detached two-line preview demonstrates alignment and line-break
handling; width, max width and the overlay distance are not previewed.

WPF's own Position / Size page and WPF behavior, the dual-text separator, a dual-specific alignment, bitmap
scale/position and any WPF percentage geometry remain outside this stage. Native desktop/DPI acceptance is separate.

The player bar gets an A-B button: left click cycles Set A → Set B → Clear, the right-click context menu exposes the
three explicit actions, and the icon is lit while at least one point is set (a muted glyph while unset, the primary
glyph while set). The seek bar gets a separate non-hit-testing overlay with one 2-DIP line per set point and a
translucent band between ordered points; the markers use the thumb-centre travel (half of the 12-DIP thumb as inset)
and never fill the host width, so the slider keeps owning all seeking. The adapter re-raises the engine's six A-B
properties under the same names and the view model mirrors them into the bound markers/button; the toast feedback
mirrors the WPF engine OSD messages — "A set", "B set", "B must be after A", and the clear toast is worded

sampled position, so neither a previously accepted B nor a playhead that advances past A during the call can turn the
result into a wrong message. Commands are guarded by `IsOpened`; points remain
transient (never persisted) and drop when a new file opens. A-B keeps the engine's priority over whole-file Loop
Playback, is inert during reverse playback and for HLS-live streams; generic non-HLS live input keeps the engine's
existing behaviour and is not a claim of this stage.

The waveform half of F-12, customizable key bindings/hotkeys (unbound by default in WPF), persistence of the A/B
points, playlists/chapters/delays/streams and bitmap/layout subtitle work are outside this stage. WPF behavior and
packaging are unchanged. The real-engine integration case is skipped when `LLPLAYER_FFMPEG_DIR`/`LLPLAYER_TEST_MEDIA`
are absent (plain focused runs) and runs inside the Windows Avalonia gate, which provides them.
