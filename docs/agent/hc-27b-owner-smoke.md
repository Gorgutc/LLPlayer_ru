# HC-27b Owner Smoke — сохранение голосов по строкам

Эта инструкция проверяет наблюдаемое поведение уже реализованного `HC-27b`: интерфейс не зависает,
последний выбранный голос сохраняется для правильного видео, настройка OFF действительно запрещает чтение и запись,
а очистка и штатный выход не оставляют устаревшее состояние.

Автотесты закрывают точные внутренние гонки очереди сохранения. Этот owner smoke нужен отдельно: только человек может
подтвердить, что реальный WPF-интерфейс остаётся отзывчивым и результат виден после повторного открытия файла.

## Что считается полным успехом

`HC-27b` можно принять только когда все шесть сценариев имеют результат `PASS`:

1. A/B isolation — два видео не смешивают назначения.
2. Latest wins — быстрое повторное назначение сохраняет последний голос.
3. Persistence OFF — при выключенной настройке companion-файл не создаётся, не меняется и не читается.
4. Clear — очистка последнего override удаляет companion-файл.
5. Exit/restart — последняя разрешённая правка переживает штатный выход и перезапуск.
6. Responsiveness — медленный/сетевой путь и большой список субтитров не замораживают UI.

`BLOCKED` или `PARTIAL` не равны `PASS`. Если нет доступной writable SMB/UNC-папки, сценарий responsiveness нужно
пометить `BLOCKED`, а `HC-27b` оставить открытым.

## Что именно сохраняется

Для видео `C:\HC27\HC27-A.mp4` LLPlayer создаёт рядом:

```text
C:\HC27\HC27-A.ru.voices.json
```

Имя строится из имени видео без последнего расширения. Это не
`HC27-A.mp4.ru.voices.json` и не файл конфигурации LLPlayer.

Ожидаемый JSON:

```json
{
  "SchemaVersion": 1,
  "Assignments": [
    {
      "StartMs": 1000,
      "EndMs": 2500,
      "VoiceId": "ru-preset-2"
    }
  ]
}
```

`StartMs` и `EndMs` идентифицируют строку субтитров, `VoiceId` — назначенный голос. Встроенные голоса:

- `Russian Narrator (M)` → `ru-preset-1`;
- `Russian Narrator (F)` → `ru-preset-2`.

Иконка голоса в строке показывает только наличие override: назначенная строка остаётся Primary/full-opacity в состоянии
покоя. Hover и keyboard focus тоже временно подсвечивают кнопку, поэтому перед оценкой отведите курсор и переведите
фокус на другой элемент. Иконка не показывает точный ID и в меню нет галочки у текущего голоса. Поэтому точный M/F
результат подтверждается JSON; новый дубляж и прослушивание строки — дополнительная end-to-end проверка, но не
обязательная часть этих шести сценариев.

## 1. Подготовить безопасные тестовые данные

Не используйте единственную копию важного видео. Создайте вне репозитория отдельную writable-папку, например
`C:\HC27`, и положите в неё три тестовые копии рабочего локального видео с текстовыми субтитрами:

```text
HC27-A.mp4
HC27-A.ru.srt
HC27-B.mp4
HC27-B.ru.srt
HC27-C.mp4
HC27-C.ru.srt
```

Расширение видео может быть другим. В каждом SRT должно быть несколько видимых строк с разными временными интервалами.
Заранее выберите по одной строке A и B так, чтобы их пары `StartMs`/`EndMs` отличались друг от друга: иначе по JSON
нельзя будет однозначно доказать, что назначения двух видео не смешались.
Перед стартом убедитесь, что рядом нет старых файлов:

```text
HC27-A.ru.voices.json
HC27-B.ru.voices.json
HC27-C.ru.voices.json
```

Если они принадлежат предыдущему тесту, сохраните их в отдельную резервную папку. Не удаляйте companion-файлы реальных
медиа.

Запишите хеши видео и SRT до проверки:

```powershell
Get-FileHash -LiteralPath "C:\HC27\HC27-A.mp4" -Algorithm SHA256
Get-FileHash -LiteralPath "C:\HC27\HC27-A.ru.srt" -Algorithm SHA256
Get-FileHash -LiteralPath "C:\HC27\HC27-B.mp4" -Algorithm SHA256
Get-FileHash -LiteralPath "C:\HC27\HC27-B.ru.srt" -Algorithm SHA256
Get-FileHash -LiteralPath "C:\HC27\HC27-C.mp4" -Algorithm SHA256
Get-FileHash -LiteralPath "C:\HC27\HC27-C.ru.srt" -Algorithm SHA256
```

После smoke эти хеши должны остаться прежними: функция меняет только `*.ru.voices.json`.

## 2. Запустить правильную сборку

Проверяйте LLPlayer `0.3.61` или новее — именно в `0.3.61` смёржен автоматизированный срез `HC-27b`.
Запишите версию, commit/источник сборки, Windows и дату.

Для локального checkout после зелёного `verify.ps1` можно запустить текущий исходный код из корня репозитория:

```powershell
dotnet run --project .\LLPlayer\LLPlayer.csproj --no-restore
```

Если проверяется готовый `LLPlayer.exe`, запишите, откуда он получен. Не смешивайте результаты разных сборок в одном
протоколе.

## 3. Найти нужные элементы UI

1. Откройте Settings одним из доступных способов: `Ctrl+,`, кнопкой-шестерёнкой или правым кликом по видео →
   **Settings**.
2. Перейдите **Subtitles → Dubbing → Persistence**.
3. Включите **Persist per-line voices**.
4. Нажмите именно **Save & Close**. `Esc` или закрытие без сохранения не подходят.
5. Откройте видео и sidebar субтитров (`Ctrl+B` или кнопка **Toggle Sub Sidebar**).
6. Справа в каждой строке, рядом с кнопкой Sync, найдите иконку человека с голосом.
7. Сделайте левый клик по ней. Меню должно содержать **Use default voice**, **Russian Narrator (M)** и
   **Russian Narrator (F)**, а также зарегистрированные custom voice IDs, если они есть.

После явного назначения отведите курсор и фокус: иконка строки должна оставаться Primary/full-opacity. После
**Use default voice** снова отведите курсор и фокус: в состоянии покоя иконка должна стать тусклой.

## 4. Как дождаться фоновой записи

Запись имеет debounce около 400 мс, но диск или сеть могут быть медленнее. В UI нет индикатора «сохранено».

Для локального диска подождите не меньше двух секунд. Затем дважды с небольшим интервалом проверьте, что размер,
`LastWriteTimeUtc` и SHA-256 companion-файла больше не меняются:

```powershell
$hc27VoicePath = "C:\HC27\HC27-A.ru.voices.json"
if (Test-Path -LiteralPath $hc27VoicePath) {
    Get-Item -LiteralPath $hc27VoicePath |
        Select-Object FullName, Length, LastWriteTimeUtc
    Get-FileHash -LiteralPath $hc27VoicePath -Algorithm SHA256
    Get-Content -LiteralPath $hc27VoicePath -Raw |
        ConvertFrom-Json |
        ConvertTo-Json -Depth 4
} else {
    "ABSENT"
}
```

На сетевом пути ждите до двух последовательных одинаковых проверок. Наличие временного файла
`.HC27-*.ru.voices.json.<id>.tmp` после завершения записи считается ошибкой.

## Сценарий 1 — A/B isolation

Цель: отложенная запись видео A не должна попасть в companion видео B.

1. Убедитесь, что persistence включён и сохранён.
2. Откройте `HC27-A.mp4` и дождитесь строк субтитров.
3. На первой строке A выберите **Russian Narrator (M)** и запишите её `StartMs`/`EndMs` из будущего JSON.
4. Не ожидая debounce, сразу перейдите к соседнему `HC27-B.mp4` через `Shift+Alt+Right` (**Open next file**). Если
   сочетание переназначено, используйте **Open next** в контекстном меню имени файла.
5. На строке B с другим временным интервалом выберите **Russian Narrator (F)**.
6. Дождитесь стабилизации обоих companion-файлов.
7. Просмотрите JSON A и B.
8. Повторно откройте A, затем B.

Ожидаемый результат:

- существуют `HC27-A.ru.voices.json` и `HC27-B.ru.voices.json`;
- A содержит ожидаемую пару `StartMs`/`EndMs` A с `ru-preset-1`;
- B содержит отличающуюся ожидаемую пару `StartMs`/`EndMs` B с `ru-preset-2`;
- ни один файл не содержит timing-пару и VoiceId, ожидаемые только для второго видео;
- после повторного открытия соответствующая строка каждого видео остаётся Primary/full-opacity в покое, после ухода
  курсора и фокуса;
- открытие одного видео не меняет companion другого.

Любое смешение A/B, отсутствие одного из итоговых файлов или изменение чужого companion — `FAIL`. Точную гонку внутри
400 мс закрепляют автоматические тесты; ручной сценарий подтверждает наблюдаемый результат быстрого переключения.

## Сценарий 2 — Latest wins

Цель: старая отложенная правка не должна затереть более новую.

1. Откройте чистый `HC27-C.mp4`.
2. На одной строке выберите **Russian Narrator (M)**.
3. Сразу снова откройте меню этой же строки и выберите **Russian Narrator (F)**.
4. Дождитесь стабилизации `HC27-C.ru.voices.json`.
5. Подождите ещё несколько секунд и убедитесь, что файл самопроизвольно не изменился.
6. Повторно откройте C.

Ожидаемый результат:

- для проверяемой пары `StartMs`/`EndMs` в JSON есть ровно одна запись;
- её `VoiceId` равен `ru-preset-2`;
- устаревшего `ru-preset-1` для этой строки нет;
- после повторного открытия voice-иконка строки остаётся Primary/full-opacity в покое, после ухода курсора и фокуса;
- точный итоговый ID по-прежнему `ru-preset-2` в JSON.

Если позже возвращается старый голос или остаются две записи одного интервала — `FAIL`.

## Сценарий 3 — Persistence OFF

Цель: OFF должен запрещать и запись, и восстановление с диска.

1. Пока persistence ещё включён, дождитесь стабильного companion C.
2. Запишите его SHA-256, размер, `LastWriteTimeUtc` и содержимое. Если файла нет, запишите `ABSENT`.
3. Откройте **Settings → Subtitles → Dubbing → Persistence**.
4. Снимите **Persist per-line voices** и нажмите **Save & Close**.
5. Повторно откройте Settings и убедитесь, что флаг остался выключенным.
6. В sidebar C выберите другой голос. Для наглядности можно сначала выбрать **Use default voice**, затем M.
7. Дождитесь завершения возможной фоновой работы и повторите проверку файла.
8. Перезапустите LLPlayer и откройте C при всё ещё выключенном persistence.

Ожидаемый результат:

- если companion отсутствовал, он не создаётся;
- если companion существовал, его SHA-256, размер, время и содержимое не меняются;
- хеши видео и SRT остаются прежними;
- внутри текущей сессии иконка может отражать новый in-memory override — это нормально;
- после перезапуска при OFF сохранённый companion не читается; после ухода курсора и фокуса иконка проверяемой строки
  тусклая.

Если OFF создаёт/меняет файл или восстанавливает его после перезапуска — `FAIL`. Точную гонку
queued-behind-save доказывает автоматический тест; этот smoke проверяет наблюдаемый итог.

## Сценарий 4 — Clear

Цель: очистка последнего override должна удалить companion и не дать ему появиться снова.

1. Снова включите persistence и нажмите **Save & Close**.
2. Откройте C и назначьте хотя бы один голос; дождитесь появления companion.
3. Для каждой иконки, которая остаётся Primary/full-opacity в покое после ухода курсора и фокуса, выберите
   **Use default voice**.
4. Проверьте обе subtitle-дорожки, если они активны: companion удаляется только когда override не осталось нигде.
5. Дождитесь стабилизации и дважды проверьте путь.
6. Повторно откройте C.

Ожидаемый результат:

- после очистки последнего override `HC27-C.ru.voices.json` удалён;
- без новой правки он не появляется снова;
- после повторного открытия проверяемые voice-иконки тусклые в покое, после ухода курсора и фокуса;
- видео и SRT не меняются.

Если файл остался, сначала проверьте другие строки и вторую дорожку. Если override нигде нет, оставшийся или повторно
появившийся файл — `FAIL`.

## Сценарий 5 — Exit/restart

Цель: штатный выход должен дождаться последней разрешённой записи и не затронуть другие медиа.

1. Persistence должен быть включён и сохранён.
2. Запишите SHA-256/время companion-файлов A и B.
3. Откройте C и назначьте **Russian Narrator (F)**.
4. Сразу выполните правый клик по видео → **App → Exit App**. Если приложение уже находится в трее, можно выбрать
   **Quit** из tray-меню. Не подменяйте этот шаг обычным сворачиванием окна.
5. Запустите LLPlayer снова и откройте C.
6. Проверьте JSON C и повторно проверьте companions A/B.

Ожидаемый результат:

- приложение штатно закрывается;
- companion C существует и содержит последний разрешённый `ru-preset-2`;
- после загрузки субтитров voice-иконка строки остаётся Primary/full-opacity в покое, после ухода курсора и фокуса;
- companions A/B не изменились;
- рядом не осталось временных `*.tmp`.

Потеря последней правки, изменение чужого companion или оставшийся temp-файл — `FAIL`. Точное ожидание Dispose/save
внутри процесса дополнительно закреплено unit-тестами.

## Сценарий 6 — Responsiveness

Цель: filesystem I/O и большой список не должны блокировать WPF dispatcher.

1. Подготовьте writable UNC/SMB-папку и чистую тестовую копию видео с текстовыми субтитрами на 5000 или больше
   уникальных cue; старого companion рядом быть не должно. Например, скопируйте видео как `HC27-NET.mp4`, задайте
   реальный сетевой путь в `$hc27NetworkSrt` и создайте детерминированный десятиминутный SRT так:

   ```powershell
   $hc27NetworkSrt = "\\server\share\HC27-NET.ru.srt"
   $hc27Rows = for ($hc27Index = 0; $hc27Index -lt 5000; $hc27Index++) {
       $hc27Start = [TimeSpan]::FromMilliseconds($hc27Index * 120)
       $hc27End = [TimeSpan]::FromMilliseconds(($hc27Index * 120) + 80)
       "{0}`r`n{1:hh\:mm\:ss\,fff} --> {2:hh\:mm\:ss\,fff}`r`nHC27 cue {0:D4}`r`n" -f `
           ($hc27Index + 1), $hc27Start, $hc27End
   }
   [IO.File]::WriteAllText(
       $hc27NetworkSrt,
       ($hc27Rows -join "`r`n"),
       [Text.UTF8Encoding]::new($false))
   ```
2. Откройте видео непосредственно по сетевому пути.
3. Включите persistence и сохраните настройку.
4. Выберите одну заранее определённую строку и 10–20 раз меняйте только её голос: M → F →
   **Use default voice**.
5. Одновременно прокручивайте sidebar, ставьте playback на паузу и продолжайте, перемещайте seek bar и окно.
6. Последним действием оставьте **Russian Narrator (F)**.
7. Дождитесь стабильной сетевой записи, откройте другое видео и вернитесь обратно.

Ожидаемый результат:

- окно не показывает **Not Responding**;
- меню, прокрутка, pause/play и seek остаются интерактивными без видимого зависания;
- сохранение может завершиться позже, но не блокирует UI;
- итоговый JSON содержит одну запись выбранной timing-пары с последним состоянием `ru-preset-2`, без очищенных
  промежуточных состояний;
- после повторного открытия иконка этой строки остаётся Primary/full-opacity в покое, после ухода курсора и фокуса;
- видео и SRT не изменены.

Любое повторяемое зависание ввода — `FAIL`; пауза примерно в секунду или дольше — очевидный жёсткий `FAIL`, а не
допустимый порог. Локальный SSD с большим SRT проверяет только
large-list часть; без настоящего writable медленного/сетевого пути ставьте `BLOCKED`, не `PASS`.

После стабилизации и после перезапуска убедитесь, что временных файлов не осталось (пустой вывод — норма):

```powershell
Get-ChildItem -LiteralPath "\\server\share" -Force -File |
    Where-Object Name -Like ".HC27-*.ru.voices.json.*.tmp" |
    Select-Object FullName, Length, LastWriteTimeUtc
```


Полезные доказательства: screenshot включённой/выключенной настройки, раскрытого voice-меню, Primary/full-opacity и
тусклой иконки в покое без hover/focus, JSON каждого companion, их SHA-256/время и короткая запись о поведении UI на
сетевом пути.

`Overall: PASS` допустим только при шести `PASS`. До этого `HC-27b` остаётся `IN-PROGRESS`.
