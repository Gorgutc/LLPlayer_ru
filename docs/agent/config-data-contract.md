# Config And Data Contract

This document freezes current config, persistence, and local data decisions from `main`.

## Runtime Config Files

Runtime JSON files live beside the exe/base directory:

- `LLPlayer.PlayerConfig.json`
- `LLPlayer.Engine.json`
- `LLPlayer.Config.json`
- `LLPlayer.WordList.json` (F-10 global word list; additive — an absent file means an empty list, no migration. Plain `System.Text.Json` array of `SavedWord` records, no polymorphic converters. Avalonia resolves it under its XDG config directory; WPF keeps its existing path/ownership.)
- `crash.log`

They are user/local state and must not be committed.

The Linux Avalonia word-library implementation wraps the shared `WordListStore` schema without changing its WPF
contract. `WordLibrary` mutations serialize a candidate and atomically write it before replacing the in-memory store;
an I/O failure leaves the published state unchanged. On malformed/unreadable input, the original file is preserved,
a warning is shown, and mutations remain blocked until an external repair or replacement. There is no import or
recovery UI and no automatic overwrite of corrupt data.

Avalonia dictionary mode is part of the detached `TranslationSettings` stored in `LLPlayer.Translation.json`; its
default is `Off`. This additive Linux setting does not rewrite the WPF `PlayerConfig.Subtitles.WordDefinitionServiceType`
value or the full Flyleaf config graph.

Avalonia subtitle/sentence translation adds `SentenceProvider` to that same detached settings record and file. It is
absent-defaulting to `Off`, including when loading an older `LLPlayer.Translation.json`; it reuses the existing
provider records, target language, and chat configuration. Primary and secondary translation switches are per-session
state: both start Off and are not persisted. Loading or saving settings makes no provider health/probe requests;
ordinary translations may resume for slots explicitly enabled in the current session after settings are applied.

## Load Order

1. `FlyleafLoader.StartEngine()` loads engine config and starts `Engine`.
2. `FlyleafLoader.CreateFlyleafPlayer()` loads player config and creates `Player`.
3. `FlyleafManager` loads app config and creates `AppActions`.

Do not reorder this without explicit migration work.

## Serialization

`AppConfig.GetJsonSerializerOptions()` uses indented JSON, string enums, typed interface converters for menu actions and translate settings, and color hex conversion. New polymorphic settings must be registered there or in the equivalent Flyleaf config serializer.

## Defaults And Migration

- Default engine keeps `PluginsPath`, `FFmpegPath`, HLS live seek, UI refresh, and FFmpeg filter load profile.
- Default player config passes HLS query options, leaves GPU adapter empty for later persistence, enables local subtitle search, and derives target translation language from original culture.
- Default custom key bindings are applied only for new config files. Exception: a newly-introduced custom action's default binding may be backfilled into an existing config when absent (e.g. `Ctrl+K` command palette), scoped to that single action so bindings the user removed for pre-existing actions are not re-added. The backfill is one-shot and chord-safe (HC-09, since 0.3.46): it runs only for configs predating `0.3.45` (the load-time version stamp then makes it never re-run, so a later intentional removal of the binding is respected), and only when the action's chord is still free — it never overwrites a chord the user reassigned to another action, which would otherwise add a duplicate binding that blocks Settings ▸ Keys Apply. The decision is the pure, unit-tested `KeyBindingBackfill.ShouldBackfill`.
- Existing key bindings may be migrated through Flyleaf config `UpdateDefault()`.
- The four A-B repeat actions (`ABLoopSetStart` / `ABLoopSetEnd` / `ABLoopClear` / `ABLoopToggle`, F-12 since 0.3.27) are appended to the END of the `KeyBindingAction` enum (persisted by name via the registered `JsonStringEnumConverter`, so existing configs are unaffected) and ship with NO default binding (assign in Settings ▸ Keys; they group under Playback). The A/B loop points themselves are transient in-memory runtime state and are never persisted.
- The seek-bar waveform toggle `ShowWaveform` (F-12, since 0.3.28) is an additive, default-false bool in the LLPlayer `AppConfig` (`LLPlayer.Config.json`), alongside the other presentation toggles (e.g. `SidebarSearch*`). It is absent-defaulting (a config predating the key loads as false → no waveform) and needs no migration; it is mirrored into the engine as `Player.WaveformEnabled` in `AppConfig.Initialize`. The decoded peak envelope is transient runtime state and is never persisted.
- Batch subtitle UI defaults live in `LLPlayer.Config.json`: last folder, recursive scan, overwrite-existing policy, and the background-friendliness knobs `SerializeAsrAndTranslate` (default `true`), `RunOnCpuWhenActive` (default `true`), and `ActiveIdleThresholdSeconds` (default `45`), plus `PreferRussianAudio` (default `true`) and `WatchFolder` (default `false`, F-09 since 0.3.22). All are additive/absent-defaulting. `PreferRussianAudio` makes batch transcribe a Russian-tagged audio track when present (so subtitles come out in Russian and translation is skipped); a per-file audio-track override in the list (`BatchSubtitleJob.AudioStreamIndexOverride`) is per-run UI state and is not persisted. `WatchFolder` makes the open batch window (or its tray-minimized session) watch the selected folder for new video files and auto-process them as they finish copying (added to the list with the same scan rules, then auto-started when no run is in progress, otherwise queued and drained when the current run finishes); it respects the same Recursive/Overwrite/friendliness settings, surfaces no new persisted state beyond the toggle, and stops when the dialog is closed. Batch processing reuses ASR/Translate settings from player config snapshots and must not silently change `TranslateTargetLanguage` or Whisper translate settings in the live player config.
- Dubbing voice config lives in `LLPlayer.PlayerConfig.json` under `Subtitles.DubbingConfig`. `DefaultVoiceId` is additive and normalized on set: trim whitespace, map null/blank to the built-in default `ru-preset-1`, and canonicalize built-in ids case-insensitively so pickers do not blank after hand edits. `CustomVoiceIds` is normalized to a non-null list, trimming entries, skipping null/blank entries, and deduping case-insensitively in declared order. The whole `DubbingConfig` is deep-copied into `BatchSubtitleConfigSnapshot` (voice id, the independent `CustomVoiceIds` list, ducking percent, atempo range, output format, TTS backend, stress normalization, engine overrides) for snapshot self-consistency and completeness-guard parity with the other nested configs (F-05-gap, closed 0.3.36), so a *future* headless/snapshot-based dub would inherit the user's Settings ▸ Subtitles ▸ Dubbing selection rather than a fresh default. No consumer reads the snapshot's `DubbingConfig` today (the live batch dub in `BatchSubtitlesDialogVM` builds its `DubbingRenderer` from the live `PlayerConfig`, not the snapshot), so there is no runtime change; with a default `DubbingConfig` the snapshot is byte-identical. Per-line `SubtitleData.AssignedVoiceId` overrides are current-session cue metadata by default: they are not serialized to config/SRT, though the batch dialog can snapshot the current open local media's assignments for the matching batch render. Opt-in persistence (`Subtitles.PersistPerLineVoices`, additive/absent-defaulting bool, default `false`, since 0.3.37) instead mirrors these overrides to a companion `video.ru.voices.json` file beside the media, keyed by SRT-millisecond cue timings (user runtime data — git-ignored and rejected from release packages like `*.ru.dub.*`; `SubtitleData` and the config JSON are still untouched): assigning/clearing a sidebar voice rewrites it atomically (clearing all overrides deletes it), opening the media restores it onto the cues, and a batch dub reads each file's companion. Default `false` → byte-identical (nothing written, restored, or read).
- Theme/appearance keys in `LLPlayer.Config.json`: `Theme.Mode` (default `Dark`; `Light`/`FollowOS` opt-in) and `AccentColorSync` (default `false`) are additive and absent-defaulting so existing configs are unchanged. `MicaBackdrop` defaults to `true` as of 0.3.2 (Win11 translucent backdrop on chrome/borders; gracefully no-ops on Windows 10 / non-Win11, never touches the DirectX video surface). New configs get it on via the property initializer; existing pre-0.3.2 configs are migrated once in `FlyleafManager.LoadAppConfig` (version-gated `< 0.3.2`, flipped on then persisted at the new version, so a user who later turns it off in Settings ▸ Themes is respected). The dark MaterialDesign2 theme remains the default appearance; Mica only affects the window backdrop. `Theme.ShowM3Theme` (T-05, since 0.3.29) is an additive, default-`false` bool that, when enabled, re-asserts the opt-in Material 3 colour overlay (`M3.Surfaces.xaml` / `M3.Accent.xaml`) on top of the live palette via `AppConfigTheme.RefreshM3Overlays` — dark theme + default Primary/Secondary colours only; it is absent-defaulting (predating configs load as `false` → stock look, byte-identical), needs no migration, and stores no other data (colour-only; control shapes are unchanged).
- `AsrOnboardingShown` in `LLPlayer.Config.json` is additive and absent-defaulting (`false`); it is set once, when the first-run ASR onboarding hint is shown, and persisted via a load-modify-save of a fresh config instance so no transient live state is committed on that path.
- ASR/translation decoding defaults (player config). `WhisperCppConfig.NoContext` defaults to `true` for new configs; existing configs are migrated once through `Config.UpdateDefault()` (version gate `<= 0.3.0`, hence the `0.3.1` app version bump that makes the migration one-shot). The migration re-applies on load until the config is saved with the new version, after which a user who turns `NoContext` back off is respected. Translate LLM defaults are additive: `TemperatureManual` defaults `false` (new configs; existing saved values are preserved), local LLM backends (LM Studio/Ollama/KoboldCpp) default `TimeoutMs` to `180000` (raised from `60000` as of `0.3.9`: the overall `HttpClient` timeout is the whole-request budget, and a reasoning model can "think" well past a minute before emitting the translation, so `60000` cancelled the request mid-reasoning — a config still on the prior `60000` default is migrated once to `180000` via `Config.UpdateDefault()` (version gate `<= 0.3.8`, hence the `0.3.9` app version bump that makes the migration one-shot), while an explicit user value is preserved and new configs default to `180000` via the settings constructors; the value stays editable in Settings ▸ Translate). The `LiteLLM` and `OpenAILike` (OpenAI-compatible) providers also default `TimeoutMs` to `180000` (T-12, since `0.3.55`): both commonly front a slow local reasoning model (LiteLLM defaults to a localhost proxy on `:4000`), so the inherited `15000` default cancelled the request mid-thought. A config still on the prior `15000` default is migrated once to `180000` via `Config.MigrateOpenAiLikeTimeoutDefault` (version gate `<= 0.3.54`, hence the `0.3.55` app version bump that makes the migration one-shot), while an explicit user value is preserved and new configs default to `180000` via the settings constructors. Cloud `OpenAI` (`ServiceType.OpenAI`) and `Claude` are out of scope and keep the base `15000` default. The local backends also apply a code-level, non-persisted `max_tokens` fallback cap so a degenerate reply fails fast. Frequency/presence penalties remain opt-in (`Manual=false`) and unchanged at defaults. The default chat-translation prompts (`TranslateChatConfig.PromptOneByOne`/`PromptKeepContext`) were rewritten for accuracy as of `0.3.5`; this is additive — a config whose saved prompt still equals the previous default is upgraded once via `Config.UpdateDefault()` (version gate `<= 0.3.4`), while a hand-edited prompt is preserved. As of `0.3.6` the default LLM chat method is `ContextWindow` (surrounding-line context plus an optional grammar pass): new configs default to it, and a config still on the prior default `KeepContext` is migrated once to `ContextWindow` via `Config.UpdateDefault()` (version gate `<= 0.3.5`, hence the `0.3.6` app version bump that makes the migration one-shot), while an explicit `OneByOne` is preserved. The new fields `PromptContextWindow`, `PromptGrammarCheck`, `ContextWindowBefore`/`ContextWindowAfter` (default `6`), and `GrammarCheckEnabled` (default `true`) are additive and absent-defaulting (existing configs pick up the new defaults on load; no migration). `FasterWhisperConfig.AntiHallucination` (default `true`) is likewise additive/absent-defaulting: it appends de-duplicated anti-hallucination decoding flags (`--condition_on_previous_text False`, `--no_speech_threshold 0.4`, `--vad_threshold 0.35`) to the faster-whisper command, only for flags the user has not already set in `ExtraArguments`, and needs no migration. `FasterWhisperConfig.Prompt` (default empty, since 0.3.11) is additive/absent-defaulting and passed as `--initial_prompt` (de-duplicated against `ExtraArguments`; an explicit `--initial_prompt` there wins) to bias the engine's language/script and casing. `WhisperCppConfig.Model.Quantization` (`QuantizationType`, default `NoQuantization`, since 0.3.21) is additive/absent-defaulting and serialized as a string via the `JsonStringEnumConverter` registered in `AppConfig.GetJsonSerializerOptions` (the options `Config.Load`/`Save` actually use): a config written before 0.3.21 has no `Quantization` key and deserializes to `NoQuantization`, which resolves the exact same legacy `ggml-{model}.bin` file (no migration). Quantized models are stored on disk as `ggml-{model}-{quant}.bin` (e.g. `ggml-base-q5_1.bin`) so they never collide with the full model; the value is mirrored into `BatchSubtitleConfigSnapshot` so batch runs use the selected quantization.
- ASR re-segmentation defaults (player config, `Subtitles`). `ResegmentSubtitles` defaults `true` (additive/absent-defaulting, applies to interactive ASR, batch, and — as of 0.3.10 — loaded/sidecar/embedded text subtitles (split on line/character overflow only, not on duration); bitmap/PGS and styled ASS cues are excluded): a long Whisper cue is split into short, at-most-`SubtitleMaxLinesPerCue`-line cues (~`SubtitleMaxCharsPerLine` chars/line) with proportionally redistributed timings, and the translated text is wrapped to the same shape; cues that already fit are left untouched. Tunables `SubtitleMaxCharsPerLine` (**48** since 0.3.7), `SubtitleMaxLinesPerCue` (**3** since 0.3.7), `SubtitleMaxCjkCharsPerLine` (**24** since 0.3.7), `SubtitleMaxCueDurationSec` (**7.0** since 0.3.7), `SubtitleMinCueDurationSec` (1.0) are additive/absent-defaulting and exposed in Settings ▸ Subtitles ▸ Re-segmentation. The 0.3.7 cap raise (2→3 lines, slightly longer lines/duration) reduces a phrase being truncated when it spans cues; values still at the prior 0.3.5/0.3.6 default (2 / 42 / 21 / 6.0) are migrated once via `Config.UpdateDefault()` (version gate `<= 0.3.6`, hence the `0.3.7` app version bump), while a user-tuned value is preserved. Line wrapping uses a balanced multi-line packer for ≥3 lines; the 2-line path is unchanged. Line breaks are stored as `\n` in `SubtitleData.Text` and honored unless `SubsIgnoreLineBreak` is on. `FixAllCaps` (default `true`, since 0.3.11) is additive/absent-defaulting: it rewrites an ALL-CAPS generated (ASR) cue to sentence-case on the interactive ASR and batch paths only (not loaded/authored subs), before re-segmentation; only a predominantly-uppercase, 2+-word cue is changed. ASR audio-chunking knobs (since 0.3.19) are additive/absent-defaulting and need no migration: `ASRSplitOnSilence` (default `true`) makes the producer prefer cutting an audio chunk at a silent frame so Whisper sees a complete phrase, with the existing `ASRChunkSize`/`ASRChunkSeconds` caps kept as a hard ceiling (`ASRSilenceSoftFraction` default `0.6` is the fraction of that budget that must accumulate before an early silent cut is allowed; `ASRSilenceRmsThreshold` default `0.01` is the normalized-RMS silence level) — it applies to interactive and batch ASR and is mirrored into the batch config snapshot. `ASRFoldBack` (default `false`) makes interactive ASR additionally transcribe the audio skipped before a mid-video start, running that earlier span first so cues stay in increasing-time order; it only affects the interactive seek path (batch transcribes from 0, so it is a no-op there) and is off by default because folding back delays subtitles appearing at the user's current position. All four are mirrored into `BatchSubtitleConfigSnapshot` for snapshot/guard parity. `ASRPerSegmentLanguage` (default `false`, T-10 since 0.3.32) is additive/absent-defaulting and likewise mirrored into `BatchSubtitleConfigSnapshot`: off, ASR pins the first detected language for the whole transcript (F-17), so it is byte-identical; on, each whisper.cpp segment / faster-whisper chunk auto-detects its own language and the per-cue `SubtitleData.Language` is recorded. It only affects the auto-detect path (a model/user-fixed language is untouched), gates the pin via the pure `AsrLanguagePolicy`, and needs no migration. `WordTimestamps` (default `true`, F-19 since 0.3.59) is additive/absent-defaulting and mirrored into `BatchSubtitleConfigSnapshot` for scalar-completeness parity: on the interactive faster-whisper path it adds `--word_timestamps` plus a JSON side output so re-segmentation times a split cue by real word boundaries instead of character proportion; it is fail-soft (a missing/mismatched word JSON falls back to proportional timing, unchanged) and needs no migration. whisper.cpp and loaded/batch subtitles are output-unaffected (the batch faster-whisper run may write/read the JSON but ignores the words). `VadCueSnapping` (default `true`, F-19 slice 2 since 0.3.60) is additive/absent-defaulting and mirrored into `BatchSubtitleConfigSnapshot` for scalar-completeness parity: on the interactive ASR path (both engines) it runs a bundled Silero VAD (ONNX Runtime, CPU) over each 16 kHz chunk and snaps re-segmentation cue boundaries onto nearby speech pauses (within a 0.5 s tolerance), layered on top of the word/character timing. It is fail-soft (a missing `Assets/silero_vad.onnx` model or any ONNX Runtime failure leaves timing unchanged) and needs no migration; batch and loaded subtitles run no VAD (output-unaffected).
- Word-definition popup config (player config, `Subtitles`, F-11 since 0.3.25). `WordDefinitionServiceType` (enum `{Off, Auto, DictionaryApi, Llm}`, default `Off`) is additive/absent-defaulting and serialized as a string via the `JsonStringEnumConverter` registered in `AppConfig.GetJsonSerializerOptions`: a pre-F-11 config has no key and deserializes to `Off`, so there is no migration and the default path is byte-identical (the word-click popup performs no definition lookup and the saved word's Reading/Definition stay blank, exactly as before). ## Actions And Key Bindings

- Custom app actions are registered by `ActionName`.
- Unknown action names should not crash config loading.
- Key matching requires exact key/modifier/enabled state.
- `IsKeyUp` actions are intentionally delayed until key-up, with a guard for missed key-up.
- Settings Keys edits the live key-binding list through an editable DataGrid. Preserve Add, Load, Apply, clone row, delete row, duplicate detection, Apply blocking on duplicates, grouped action selection, custom action names, key capture, and Enter commit.
- CheatSheet reads only enabled key bindings, groups them by action group, filters by action description or shortcut text, and can execute an action from the dialog.
- The Command Palette (`Ctrl+K`) reuses the same enabled-key-binding list as a flat, filterable dialog and runs the selected action's delegate (`ActionInternal`).
